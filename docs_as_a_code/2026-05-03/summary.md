## Kaleidoscope言語のコンパイラ実装など

### LLVMの概要

LLVMプロジェクトの公式サイトを翻訳しながら、LLVMの全体像を把握した。

参考: [LLVM公式サイト](https://llvm.org/)

基本情報:

- LLVMはモジュール式で再利用可能なコンパイラおよびツールチェーン技術の集合体である
- イリノイ大学での研究プロジェクトとして始まり、任意のプログラミング言語の静的・動的コンパイルをサポートする
- 「LLVM」という名前は頭字語ではなく、プロジェクトの正式名称である。従来の仮想マシンとはほとんど関係がない
- Apache 2.0ライセンス（LLVM例外付き）の下でライセンスされている

主要サブプロジェクト:

- **LLVMコアライブラリ**: ソース・ターゲット非依存のオプティマイザと、多数のCPU向けコード生成サポートを提供する
- **Clang**: C/C++/Objective-Cコンパイラ。Macに標準で入っているCコンパイラでもある
- **LLDB**: 高品質なネイティブデバッガ
- **libc++/libc++ ABI**: C++標準ライブラリの実装。コンパイル時のログで見かけることがある
- **MLIR**: 中間表現（IR）を扱う、再利用可能で拡張性のあるコンパイラ基盤を構築するための新しいアプローチ
- LLVMの強みは汎用性・柔軟性・再利用性にあり、Ruby、Python、Haskell、Rust、D、PHPなど多くの言語をコンパイルできる

---

### Kaleidoscope言語チュートリアルの概要

LLVMの学習のため、Kaleidoscope（万華鏡）というおもちゃの言語を使ったチュートリアルに取り組むことにした。

参考: [LLVM Tutorial: Table of Contents](https://llvm.org/docs/tutorial/index.html)

言語の特徴:

- 関数の定義、条件分岐、数学演算などを可能にする手続き型言語である
- データ型は64bit浮動小数点型（倍精度）のみで、型宣言が不要なシンプルな設計となっている
- Fibonacci数列の計算や、`extern`キーワードによる標準ライブラリ関数の呼び出しが可能
- 最終目標は第6章でマンデルブロ集合を様々な倍率で表示する小さなアプリケーションを作成すること

実装方針:

- コンパイラの実装言語はC++を使用する
- チュートリアルの全コードは`toy.cpp`という単一ファイルに記述する

### 字句解析（Lexer）の実装

字句解析とは、テキストファイルをトークンに分割する処理である。例えば`int a = 10;`は、キーワード（int）、識別子（a）、代入（=）、整数（10）、セミコロン（;）のトークン列に変換される。

トークンの設計:

- トークンの種類として、EOF、DEF、EXTERN、IDENTIFIER、NUMBERをenum定義する
- enumの値をマイナス側（-1, -2, ...）に設定し、0〜255のASCII文字コード範囲は演算子などの不明な文字用に確保している。これにより`+`や`-`はASCII値そのものをトークンコードとして返せる
- トークンがIDENTIFIERの場合、`identifier_string`グローバル変数に識別子名が格納される
- トークンが数値リテラルの場合、`num_val`に値が格納される

`GetTok()`関数の処理フロー:

- 標準入力から1文字ずつ読み込み（`getchar()`）、次のトークンを返す
- スペースは読み飛ばし、コメント（`#`から改行まで）も読み飛ばす
- 先頭文字がアルファベット（`isalpha`）の場合: アルファベットまたは数字（`isalnum`）が続く限り`identifier_string`に蓄積する。結果が`def`なら`tok_def`、`extern`なら`tok_extern`、それ以外なら`tok_identifier`を返す
- 先頭文字が数字またはドット（`isdigit`または`.`）の場合: 文字列として蓄積し、C言語の`strtod`関数で数値に変換して`num_val`に格納し、`tok_number`を返す
- `#`の場合: 改行まで読み飛ばし、再帰的に`GetTok()`を呼び出して次のトークンを返す。コメント自体はトークンとして処理されない
- EOFの場合は`tok_eof`、それ以外の文字はASCII値をそのまま返す

### 抽象構文木（AST）の設計

ASTはコンパイラの後段（コード生成など）が解釈できるようにプログラムの動作を捉えるものである。言語の構文（括弧やカンマなど）には言及せず、実行に必要な情報のみを保持する。

ノードの種類:

- **ExprAST**: 全ての式の基底クラス。C++のvirtual関数（インターフェース的な役割）とvirtualデストラクタを持つ。デストラクタはオブジェクト削除時のメモリ解放に必要で、Rustではこの概念が言語レベルで解消されている
- **NumberExprAST**: 数値リテラル用。数値をインスタンス変数として保持する
- **VariableExprAST**: 変数用。変数名を保持する
- **BinaryExprAST**: 二項演算用。演算子（`+`、`-`など1文字のchar）と左辺・右辺のExprASTポインタを持つ
- **CallExprAST**: 関数呼び出し用。関数名と引数リスト（`vector`）を持つ

関数の表現:

- **PrototypeAST**: 関数のプロトタイプ（関数名と引数名のリスト）を表現する。ExprASTは継承しない。Kaleidoscopeでは全ての値が倍精度浮動小数点数のため、引数や戻り値の型情報は不要
- **FunctionAST**: プロトタイプとボディ（ExprAST）から構成される関数定義を表現する

プロトタイプ宣言の概念:

- C++では関数の実体がどこかにあることを先に宣言しておく仕組みがある。上から順に読むため、宣言がないと呼び出し時にエラーになる
- 最近の言語ではこのような前方宣言が不要なことが多い

### 構文解析（Parser）の基本概念

再帰下降構文解析と演算子優先順位構文解析を組み合わせてKaleidoscope言語を解析する方針を確認した。

参考: [構文と意味論（慶應義塾大学）](https://web.sfc.keio.ac.jp/~hattori/prog-theory/ja/syntax-and-semantics.html)

生成規則と再帰下降構文解析:

- 生成規則（BNF記法）とは、言語の構造を定義する規則のことである。例えば「式（Expression）とはプライマリの後にバイナリ演算子とプライマリの組が0個以上続くもの」のように定義する
- 各生成規則に対応するパース関数を実装し、外側から内側へと対応する関数を呼び出していく手法が再帰下降構文解析である
- 式の中に式が含まれる場合（例: 括弧式）は再帰的に呼び出されるため「再帰」と呼ばれる

パーサーの構造:

- トークンバッファ: `CurTok`が現在のトークン、`getNextToken()`が次のトークンを取得して`CurTok`に格納する
- `ParseExpression()`: 式全体をパースする。まず`ParsePrimary()`で左辺を取得し、続くバイナリ演算子と右辺の組を処理する
- `ParsePrimary()`: 現在のトークンに応じて分岐する。IDENTIFIERなら`ParseIdentifierExpression()`、NUMBERなら`ParseNumberExpression()`、`(`なら括弧式のパースを呼び出す
- `ParseNumberExpression()`: 数値リテラルからNumberExprASTを生成して返す
- トップレベルのメインループでは、先頭トークンが`def`なら関数定義、`extern`ならextern宣言、それ以外ならトップレベル式としてそれぞれのパース関数を呼び出す
- エラー処理用の`LogError`関数を用意している

バイナリ演算子の処理:

- 二項演算子は`+`、`-`、`*`、`/`など1文字の演算子を想定しており、演算子の種類による分岐は不要。演算子の文字をそのまま`BinaryExprAST`の`Op`に格納し、評価時に処理を分ける設計となっている
