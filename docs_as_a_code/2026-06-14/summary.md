## LLVM IRコード生成の実装など

### 概要

LLVMのチュートリアルを使って、Kaleidoscope言語のコンパイラ実装を学習している。前回は抽象構文木（AST）の設計とパーサーの実装を進めており、今回はChapter 3のASTからLLVM IRへのコード生成を読み進めた。あわせてSSA（静的単一代入）の概念をWikipediaで補足し、最後にRustコンパイラの中間表現（THIR）で実際のIRの外形を確認した。

参考資料:

- [LLVM Tutorial: Implementing a Language with LLVM - Chapter 3](https://llvm.org/docs/tutorial/MyFirstLanguageFrontend/LangImpl03.html)
- [Wikipedia: 静的単一代入形式（Static single-assignment form）](https://en.wikipedia.org/wiki/Static_single-assignment_form)
- [Rust Compiler Development Guide: The THIR](https://rustc-dev-guide.rust-lang.org/thir.html)

### IR（中間表現）とは

コード生成に入る前提として、IR（Intermediate Representation, 中間表現）とは何かを確認した。

ポイント:

- 元の言語から直接バイナリに変換するのではなく、一度別の中間的な表現に変換するもの。別のプログラミング言語のコードを一度作るようなイメージ
- LLVM IRまで変換できれば、あとはLLVMが最適化・コンパイルを担ってくれる
- 中間表現のメリット: x86・ARM等のCPUアーキテクチャに依存しない形で表現でき、同じIRから複数のターゲットへコンパイルできる。クロスコンパイルに向かっていける
- インタプリタは字句解析・構文解析をして評価（実行）するコードを書くためコンパイルしないが、ここから先のIR生成は未経験の参加者が多く、知らない領域だという話になった

### SSA（静的単一代入）とは

LLVMの`Value`クラスが採用しているSSA（Static Single Assignment, 静的単一代入）形式について、Wikipediaを参照して理解を深めた。

概念:

- 各変数に対して「ちょうど1回だけ代入する」という制約を持つ中間表現の形式
- LLVMの`Value`は、関連する命令の実行時に値が計算され、再実行されるまで新しい値を取得しない。一度計算した値を変更する方法がない
- LLVM IRもプログラミング言語のようなものだが、同じ変数にはちょうど1回しか代入を書いてはいけない。この制約を満たすものをSSA形式と呼び、LLVM IRはSSA形式を採用している

通常のコードからSSA形式への変換:

- 既存の変数に複数回代入するコードは、代入のたびに別名（添え字付きのバージョン、例: `x1`, `x2`）を割り振ることで機械的にSSA形式へ変換できる。これによりプログラムの実行内容は変わらない
- 例: `x`に複数回代入していたものを `x1`, `x2`, `x3` と振り直すと、同じ変数への複数回代入が一箇所もなくなる

ファイ（Φ）関数:

- `if`文などの分岐で、実行パスによって異なる変数（例: `y1` か `y2` か）が同じ場所で使われる場合に挿入される特殊なステートメント
- `x`は使う順に番号を振れば見通しよく変換できるが、分岐先で代入する値が変わる`y`のような変数は、後続のブロックで`y1`なのか`y2`なのか定まらない。この合流点でいずれかを選択するのがファイ関数の役割
- 詳細はコードを動かしてみないと直感的に理解しづらく、実際に手を動かして確認する方が早いという結論になった

### 式ノードのコード生成

Chapter 3の基本設定と、4つの基本式ノードに対するコード生成を読んだ。式ノードのコード生成は45行未満で書けるほど単純である。

基本設定:

- `codegen()`メソッドはASTノードに対応するLLVM IR（`llvm::Value*`）を返す。ビジターパターンで実装する選択肢もあるが、チュートリアルでは仮想メソッドを追加する最も簡単な方法を採用している
- 主要なオブジェクト:
  - `TheContext`: 型テーブルや定数値テーブルなど、多くのコアLLVMデータ構造を所有する。中身を理解する必要はなく、それを必要とするAPIに渡す単一のインスタンスがあればよい
  - `Builder`: IR命令の生成を補助するヘルパーオブジェクト。新しく作成した命令をどこに挿入すればよいかを知っている
  - `TheModule`: 関数やグローバル変数を含むLLVMの最上位構造。生成されるすべてのIRのメモリを所有するため、`codegen()`は生のポインタを返す
  - `NamedValues`: 現在のスコープで定義されている値とそのLLVM表現を保持するシンボルテーブル。この時点のKaleidoscopeで参照できるのは関数のパラメータのみ

各ASTノードのコード生成:

- **NumberExprAST**: `ConstantFP::get()`で数値定数を生成する。`APFloat`（任意精度の浮動小数点数）でラップした値を渡すだけでよい。LLVMでは定数は1意に識別されて共有されるため、`new`/`create`ではなく`get`イディオムを使う（一度作った定数は2回目以降は作り直さない）
- **VariableExprAST**: `NamedValues`マップから変数名に対応する値を検索して返す。マップになければ未定義変数の参照としてエラーにする。`NumberExprAST`とは兄弟関係のノードで、`Variable`側は変数名（`name`インスタンス変数）を持つ
- **BinaryExprAST**: 左辺・右辺をそれぞれ再帰的にコード生成し、演算子に応じた命令（`CreateFAdd`等）を`Builder`で生成する。左辺・右辺はどこまでも深くなりうる式（`1 + 1 + 1`なら右側がさらに`BinaryExprAST`）だが、とにかく左を生成・右を生成して演算するという構造になる
  - 命令は厳格な型ルールで制約されており、加算の左右オペランドと結果は同じ型でなければならない。Kaleidoscopeは全ての値が`double`型なので加減乗算のコードは非常にシンプルになる
  - `<`演算子は、LLVMの`CreateFCmpULT`が1ビット整数を返す。Kaleidoscopeでは値が`0.0`または`1.0`である必要があるため、`UIToFP`命令で1ビット整数を符号なし整数として`0.0`/`1.0`の浮動小数点数に変換する
- **CallExprAST**: `TheModule->getFunction()`で関数名（呼び出される関数の名前を保持するインスタンス変数）を検索し、各引数をコード生成して`ArgsV`に積み、`CreateCall`で呼び出し命令を生成する。引数の個数が違えばミスマッチとしてエラーにできるが、全ての値が`double`型のため型チェックは個数の確認だけで済んでいる。LLVMはデフォルトでネイティブCの呼び出し規約を使うため、`sin`や`cos`などの標準ライブラリ関数も呼び出せる

命令への名前付け:

- `CreateFAdd`等で生成する命令には任意で名前（例: `addtmp`）を付けられる。重複しないよう自動的に連番のサフィックスが付与される
- 名前付けは必須ではなく、IRダンプを読んだときに`addtmp =`のような箇所を見つけやすくするデバッグ用途の意味合いが強い

### プロトタイプのコード生成

関数のプロトタイプ（外部インターフェース）のコード生成を読んだ。プロトタイプは関数本体と外部関数宣言（`extern`）の両方で使われる。

実装内容:

- Kaleidoscopeの全引数は`double`型なので、まず引数の個数分の`double`型ベクター（`Doubles`）を作る
- `FunctionType::get()`で関数の型を作る。N個の`double`型を引数に取り、1つの`double`型を返す型を指定する。最後の`false`引数は可変長引数ではないことを示す
- `Function::Create()`で型・リンケージ・名前・挿入先のモジュールを指定し、IR関数オブジェクトを実際に作成する。プロトタイプは値ではなく関数を返す点に注意する

外部リンケージ（ExternalLinkage）:

- 関数が現在のモジュールの外に定義でき、かつモジュール外の関数からも呼び出せることを意味する
- 全てのグローバル変数・関数は何らかのリンケージを持つ。プライベートリンクなら現在のモジュール内からのみアクセス可能。`extern`で広く外から使える関数にはExternalLinkageを与える

引数への名前付け:

- 関数を作成した後、`Args`（プロトタイプが持つ引数名一覧）をループしながら各引数に名前を設定する。関数作成時には型と関数名しか決まっておらず、引数の名前はこの段階で設定する
- この手順は必須ではないが、名前を統一しておくとIRの可読性が向上する。デバッグ時に生成されたIRを見たとき、引数が`V1`/`V2`のような自動採番ではなく実際の名前で表示されるため何を指しているか分かりやすい

`extern`で十分な理由:

- `sin`や`cos`などの標準ライブラリ関数は、本体がLLVMモジュールにとって既知（外部の標準ライブラリに実体がある）なので、プロトタイプだけ宣言しておけば呼び出せるようになる
- 一方、自分たちで書いた関数の定義はLLVMがまだ知らないため、本体を解析する必要がある。`extern sin(arg)`のように宣言を書いておかないと、その関数の存在に気づけない

### 関数本体のコード生成

プロトタイプに本体を加え、`FunctionAST`（プロトタイプ＋ボディ）をコード生成する流れを読んだ。コード生成時に関数が実行されるわけではなく、「関数が実行されたときに何を行うか」を組み立てている点を整理した。

実装の流れ:

- まず`TheModule->getFunction()`でプロトタイプ名の関数を検索する。`extern`で既に作られていればそれを使い、なければプロトタイプからコード生成する。いずれの場合も開始前に関数本体が空であることを確認する
- `BasicBlock::Create()`で`entry`という名前の基本ブロックを作り、`Builder`の挿入ポイントをそこに設定する。`BasicBlock`の作成時に`TheFunction`を渡しているため、このブロックは関数に紐づく。以降のコード生成はこの基本ブロック内（＝関数内部）に挿入されていく
- 制御フローがまだないため現時点では関数に基本ブロックは1つしか含まれない。`if`文などは第5章で対応する想定

NamedValuesのクリアと引数の登録:

- `NamedValues`をクリアしてから関数引数を登録する。`NamedValues`はグローバルに保持されるため、クリアしないと前回の呼び出し時のゴミデータが残ってしまう
- ここで登録するのは実行時の値ではなく、「こういう変数が存在する」というコード生成時の情報である。ボディのコード生成中に`VariableExprAST`が現れたら、`NamedValues`から対応する引数を参照できるようにするためのもの
- 例: 引数`x`を受け取り本体が`x`だけの関数では、ボディのコード生成時に`VariableExprAST`が`NamedValues`から`x`を探す。この時点で`x`が登録されていないと困るため、事前のクリア＆登録が必要になる

本体の生成と検証:

- ルート式（ボディ）の`codegen()`を呼び、計算された値を`RetVal`に得る。挿入ポイントが設定済みなので、生成される命令は`entry`ブロック（＝関数）内に書かれていく
- `CreateRet()`でリターン命令を作成し、関数を完成させる。`return x`のような本体なら、`x`を参照する命令とそれを返す命令がブロック内に作られる
- `verifyFunction()`で生成コードの整合性チェックを実施する。`TheFunction`しか渡していないが、基本ブロックが関数に紐づいているため本体のチェックも行われる（例: `double`を返す関数が誤った型を返していないか等）。エラーがあれば`eraseFromParent()`で関数を削除する

補足:

- LLVM周りはポインタや間接的な参照が多くブラックボックスに見えて追いづらいという感想が出た。チュートリアルのこのコードにはわざと仕込まれたバグ（同名関数の再定義に関するシャドウイング）があると示唆されているが、今回は深追いしなかった

### 実際のIRの確認（Rust THIR）

LLVM IRが具体的にどのような見た目をしているのかを確かめるため、ドライバー部分の出力例と、Rustコンパイラの中間表現THIRのドキュメントを参照した。

ドライバー出力の確認:

- `4 + 5;`と入力すると、`4`と`5`を別々に評価して足すIRが出ると予想していたが、実際には定数畳み込み（最適化）が効いて`9`を直接返すようなIRが出力された
- LLVM IRはテキストをベタ書きしていくものだと想像していたが、実際はライブラリのAPIを使ってC++側で構築していく形だった

中間表現の段階とテキスト表現:

- 言語によっては中間表現が複数段階あり、Rustでは`HIR`・`THIR`・`MIR`などの段階を経て最終的にLLVM IRに至る
- THIRのドキュメントで`ExprKind`（`Literal`, `Scope`, `Binary`の`Add`等）が木構造で表現されているのを確認した。例えば`x = 1 + 2`は、`Expr4`が`1 + 2`を表し、LHS=`E1`（`1`）、RHS=`E3`（`2`）、operation=`Add`として表現される
- IRはテキスト形式である必要はなく、機械的にはASTのまま扱うのが自然である。`x1 = ...`のようなテキスト表現は人間が読むための都合に過ぎない
